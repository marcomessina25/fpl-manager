# V0.8 — Predictive Participation, Rank-Aware Decisions & Football Context

> **Living milestone plan.**
>
> V0.8 is the first model-improvement milestone after V0.7. V0.7 established the historical measurement and backtesting framework; V0.8 should use that framework to improve the predictor and decision system based on measured failure modes.
>
> **Current baseline:** `v07` has implemented historical ingestion, point-in-time reconstruction, xP/xM/availability backtesting, sequential decision simulation, deterministic optimizer evaluation, LLM A/B evaluation, and cross-season reporting. The latest V0.7 results provide the evidence that drives this plan.

---

# 1. Executive objective

The primary objective of V0.8 is:

> **Improve the quality of the player participation prediction and then measure whether that improvement translates into better FPL decisions.**

The V0.7 results point to a clear priority:

```text
Current xP
    ↓
meaningful predictive signal

Current xM / participation
    ↓
largest identified weakness
    ↓
especially players in the rotation / partial-minutes region

Optimizer
    ↓
already materially better than simple baselines
```

Therefore V0.8 should **not** begin as a generic feature-expansion release.

The first priority is to improve the model's ability to answer:

> **"Will this player actually start or play this Gameweek, and for how many minutes?"**

Only after that should we expand the objective from expected points toward rank-aware utility and add richer football context.

---

# 2. What V0.7 taught us

V0.7 has changed the development process from subjective model tuning to measurable experimentation.

The historical results show:

- xP has meaningful rank-ordering signal;
- xP error is relatively stable across the tested historical seasons;
- expected minutes are substantially less accurate;
- the largest xM errors occur in intermediate/rotation ranges;
- the current FPL availability flag is insufficient to predict actual participation;
- the deterministic optimizer outperforms the simple xP and no-transfer baselines in the tested simulations;
- LLM overrides of the mathematical optimizer did not provide measurable benefit in the tested setup.

These conclusions mean that V0.8 should **preserve the current deterministic architecture while improving its weakest predictive component**.

# 4. Phase 0 — Close V0.7 cleanly

Before modifying the model, finish the remaining V0.7 validation work.

This is not a new feature milestone. It is the final baseline establishment needed to make V0.8 scientifically useful.

## 4.1 Full-season strategy replay

Where the current branch supports the required historical data, run the deterministic strategy comparison over complete seasons rather than relying on shorter initial windows.

At minimum compare:

```text
No Transfer
Simple xP
Production Optimizer
```

using identical starting conditions.

Record:

- total points;
- net points;
- gross points;
- transfers;
- hits;
- Gameweek-by-Gameweek delta;
- cumulative delta;
- mean delta;
- median delta;
- variance;
- number of Gameweeks won/lost/tied.

The goal is to establish a stable V0.7 benchmark.

## 4.2 Leakage audit

The point-in-time contract must be verified before using historical results to train or tune anything.

For each Gameweek N:

```text
Allowed:
    GW 1 ... GW N-1 outcomes
    pre-GW-N information
    GW-N fixture information known before deadline

Forbidden:
    GW-N final points
    GW-N final minutes
    GW-N final bonus
    GW-N post-match statistics
    future prices
    future ownership
    future transfers
```

A particular area to audit is historical reconstruction of player status/availability.

The V0.7 snapshot implementation deliberately reconstructs cumulative historical statistics from GW1..N-1, while using the current Gameweek player record for some current player attributes. This must be verified field-by-field so that no post-match GW-N outcome can influence the prediction.

## 4.3 Freeze the V0.7 baseline

Once the baseline experiments are reproducible:

- record the exact V0.7 commit;
- record dataset versions;
- record configuration;
- preserve baseline results;
- do not silently replace them when V0.8 begins.

V0.7 becomes the control experiment against which V0.8 is measured.

# 5. Phase 1 — Build the participation-error dataset

This is the first substantive V0.8 task.

The current model effectively needs to estimate:

```text
P(play)
P(start)
expected minutes
```

while the FPL API's availability state does not provide sufficient information to distinguish all real-world non-appearances.

The first step is therefore not model training.

It is **error decomposition**.

## 5.1 Create a player-GW diagnostic table

For every historical player/Gameweek, store:

```text
season
gameweek
player_id
team_id
position
price
predicted_availability
predicted_start_probability
predicted_expected_minutes
actual_started
actual_minutes
actual_points
recent_minutes
recent_starts
historical_minutes
historical_starts
fixture_context
```

Where available, also store:

```text
days_since_previous_fixture
days_until_next_fixture
matches_last_7_days
matches_last_14_days
European/cup proximity
manager/team context
injury/status information
```

## 5.2 Identify high-confidence false positives

Create a dedicated view for:

```text
high predicted P(play/start)
+
actual minutes = 0
```

and:

```text
high predicted expected minutes
+
actual minutes = 0
```

These are much more informative than aggregate MAE.

## 5.3 Identify large-minute errors

Also isolate:

```text
predicted 60–90
actual 0–30
```

and:

```text
predicted 0–30
actual 60–90
```

The first category is likely to be particularly damaging to FPL decisions.

---

# 6. Phase 2 — Decompose rotation, injury and tactical failure

Do not treat every zero-minute false positive as the same phenomenon.

The analysis should classify cases, where the available historical evidence allows it, into:

1. Rotation/rest.
2. Injury/fitness.
3. Suspension.
4. Tactical omission.
5. Role change.
6. Competition/cup rotation.
7. Transfer/team transition.
8. Unknown/data limitation.
9. Genuine model miss.

The initial classification can be partly manual on a representative sample.

The objective is to determine:

> **What percentage of our participation errors is caused by each phenomenon?**

This tells us which features are worth implementing.

---

# 7. Phase 3 — Replace "availability" with a participation model

The current model should evolve from a simple availability interpretation toward explicit probabilities.

Conceptually:

```text
                 Player state
                     │
          ┌──────────┴──────────┐
          ▼                     ▼
       P(start)             P(sub)
          │                     │
          └──────────┬──────────┘
                     ▼
              Expected minutes
                     │
                     ▼
                    xM
                     │
                     ▼
                    xP
```

The precise probabilistic decomposition can be refined during implementation, but the separation is important.

## 7.1 P(start)

Estimate:

> Probability that the player starts the fixture.

Candidate inputs:

- recent starts;
- recent minutes;
- season starts;
- season minutes;
- start-rate trend;
- minutes trend;
- player position;
- player price;
- team strength;
- role stability;
- team congestion;
- turnaround time;
- nearby European fixtures;
- nearby domestic cup fixtures;
- manager rotation tendencies;
- player-specific rotation tendencies;
- historical availability information.

## 7.2 P(sub appearance)

Estimate:

> Probability that the player appears if they do not start.

This matters because a substitute appearance still generates appearance points and some opportunity for attacking/bonus contributions.

## 7.3 Expected minutes conditional on start

Estimate:

```text
E[minutes | starts]
```

This should distinguish:

- nailed starters;
- players normally substituted early;
- returning-from-injury players;
- players managed for fitness.

## 7.4 Expected minutes conditional on substitution

Estimate:

```text
E[minutes | substitute appearance]
```

This can initially be a simple empirical estimate and become more sophisticated only if the data justifies it.

# 8. Phase 4 — Establish a simple model before a complex model

Do not immediately build a deep-learning participation model.

The first experiment should establish a strong, interpretable baseline.

Candidate models:

```text
Logistic Regression
Gradient Boosting
Random Forest
```

for start/appearance classification.

For expected minutes, test a suitable regression or two-stage model.

The purpose is to determine whether a dedicated participation model actually improves on the current heuristic.

The benchmark must remain:

```text
V0.7 current xM
```

not an arbitrary new model.

---

# 9. Phase 5 — Rotation-specific feature engineering

Once the basic participation model exists, introduce the features most directly motivated by V0.7's failure analysis.

## 9.1 Fixture congestion

Calculate:

```text
matches_last_7_days
matches_last_14_days
matches_last_21_days
days_since_last_match
days_until_next_match
```

and competition-aware variants where reliable historical fixture information exists.

## 9.2 European competition

Capture proximity to:

- Champions League;
- Europa League;
- Conference League.

Test separately:

```text
European match before FPL fixture
European match after FPL fixture
short turnaround after European match
```

Do not assume these variables help. Measure them.

## 9.3 Domestic cups

Where historical fixture data supports it, include nearby:

- FA Cup;
- League Cup.

Again, use the feature only if out-of-sample evaluation demonstrates value.

## 9.4 Recent role

Compare:

```text
season start rate
last 10 start rate
last 5 start rate
last 3 start rate
```

The model should be able to react when a player's role changes.

---

# 10. Phase 6 — Player-specific rotation signatures

Aggregate historical starts are insufficient for some players.

Create features describing player-specific patterns.

Examples:

```text
start_rate_normal_rest
start_rate_short_rest
start_rate_after_Europe
start_rate_after_cup
average_minutes_when_starting
sub_probability
zero-minute rate
```

Potentially:

```text
P(start | congestion)
P(start | normal schedule)
```

This should allow the model to learn that different players behave differently under the same fixture conditions.

---

# 11. Phase 7 — Manager and team behaviour

Manager behaviour should be introduced carefully.

Useful features may include:

```text
team rotation rate
manager rotation rate
position-specific rotation rate
player rotation relative to team
```

The model should eventually be capable of distinguishing:

```text
"this team rarely rotates"
```

from:

```text
"this team rotates its fullbacks heavily"
```

and:

```text
"this specific player is particularly affected."
```

Manager changes should be treated as regime changes rather than blindly mixing pre- and post-change observations.

---

# 12. Phase 8 — Role-transition detection

Identify transitions such as:

```text
starter → rotation
rotation → starter
starter → injury
injury → starter
new signing → established role
manager change → role change
```

Then measure model performance specifically around those transitions.

If errors are concentrated around role transitions, the model needs stronger recency/regime-change handling rather than simply more historical data.

---

# 13. Phase 9 — Oracle experiments

Before investing heavily in the new model, quantify the theoretical value of fixing participation.

These are **diagnostic experiments only** and must never be treated as predictive results.

## 13.1 Perfect-minutes experiment

Replace predicted minutes with actual minutes for the historical evaluation.

Compare:

```text
current xP
vs
xP with actual minutes
```

This measures the maximum potential value available from eliminating minutes error.

## 13.2 Perfect-participation experiment

Replace participation probability with the actual participation outcome.

Compare:

```text
current xP
vs
xP with perfect participation
```

The difference tells us how much predictive/decision loss is attributable to participation uncertainty.

## 13.3 Decision-level oracle

Run the optimizer with perfect historical participation information only as an offline diagnostic.

Measure:

```text
current optimizer
vs
optimizer with oracle participation
```

This estimates how many points are potentially recoverable.

# 14. Phase 10 — Evaluate xM using decision-aware metrics

Do not rely only on:

- MAE;
- RMSE.

Also measure:

```text
high-P(start) but 0-minute rate
high-xP player 0-minute rate
selected-player 0-minute rate
captain 0-minute rate
false-starter rate
false-bench rate
```

And:

> **points lost because of participation prediction errors.**

This is the metric that connects model quality to the application's actual purpose.

Once the participation model demonstrates improvement:

```text
V0.7 xP scoring components
+
```

# 16. Phase 12 — Decision-level A/B test

This is the most important acceptance test.

Compare V0.7 and V0.8 on identical historical simulations.

Measure:

### Prediction

- xP MAE;
- xP RMSE;
- Spearman;
- xM MAE;
- xM RMSE;
- calibration.

### Decision

- total points;
- net points;
- Gameweek wins;
- transfer count;
- hit count;
- transfer ROI;
- bench points;
- captain points;
- zero-minute selected players.

### Regret

- missed opportunity;
- rotation-related regret;
- captaincy regret;
- transfer regret.

V0.8 should not be considered successful simply because xM MAE improves.

It should demonstrate that the improvement is useful to the decision engine.

# 17. V0.8 success criteria for the participation model

Targets should be evidence-driven, but the following are useful working goals.

## Statistical

Improve substantially over the V0.7 baseline:

```text
xM MAE ≈ 18–19 minutes
```

with particular emphasis on the:

```text
16–60 minute prediction range
```

where V0.7 performs worst.

## Classification

Improve:

```text
P(start)
P(play)
```

precision without destroying recall.

## Decision

Reduce:

```text
high-projection zero-minute selections
```

and demonstrate measurable improvement in simulated net points.

The exact numerical threshold should be finalized after the baseline is frozen.

# 19. Phase 14 — Rank-aware optimisation

After predictive improvements, V0.8 should begin moving beyond:

```text
maximize expected points
```

toward:

```text
maximize strategic utility
```

Candidate objectives:

```text
Expected points
Expected rank gain
Expected rank loss
Probability of beating benchmark
Probability of top-k finish
Downside percentile
Risk-adjusted utility
```

A configurable generic utility can be represented conceptually as:

```text
U =
    expected_points
  + α × rank_leverage
  - β × downside_risk
  - γ × transfer_cost
```

The coefficients must be configurable.

Do not hard-code one universal risk preference.

---

# 20. Risk profiles

The optimizer should eventually support explicit strategic profiles.

## Neutral

Maximize expected outcome.

## Floor

Protect against downside and minimize rank loss.

## Ceiling

Accept variance for upside.

## Defend lead

Prioritize minimizing catastrophic rank loss.

## Chase

Prioritize probability of substantial rank gain.

The same player set may therefore produce different optimal decisions depending on the manager's strategic objective.

# 23. Phase 16 — LLM as qualitative analyst

V0.7's LLM A/B experiment should change how we use the LLM.

The current evidence does not justify making the LLM a numerical optimizer.

Preferred architecture:

```text
Deterministic engine
        ↓
5–20 viable strategies
        ↓
structured comparison
        ↓
LLM critique
        ↓
qualitative evidence
        ↓
deterministic validation
        ↓
human decision
```

The LLM should focus on:

- tactical context;
- injury uncertainty;
- rotation risk;
- set pieces;
- fixture-specific factors;
- hidden assumptions;
- potential traps.

It should not be trusted to perform FPL legality or numerical optimisation.

---

# 24. LLM and football information should remain separate concepts

An LLM can help interpret information, but it should not become the data source of truth.

Prefer:

```text
source
 ↓
structured observation
 ↓
confidence
 ↓
model feature
```

over:

```text
LLM says player is injured
 ↓
model blindly believes LLM
```

The LLM should operate on structured facts where possible.

---

# 25. Provider strategy

The V0.65/V0.7 OpenRouter integration provides the current free-capable provider path.

V0.8 should therefore not block development on finding another provider.

Provider abstraction should remain configurable:

```text
provider
model
API configuration
prompt version
```

Additional free providers can be evaluated later for redundancy and A/B experiments.

The numerical decision engine must remain fully functional without an LLM.

# 28. Temporal train/test discipline

If the new participation model is trained using historical data, all training must respect time.

Do not train on future Gameweeks and evaluate on earlier Gameweeks.

Preferred structure:

```text
Historical data
      ↓
training period
      ↓
validation period
      ↓
out-of-sample test period
```

The exact season split should depend on the available datasets.

Within-season rolling evaluation is also preferable to random row splitting because FPL is a temporal process.

---

# 29. Data-quality requirements

Before training a new model, validate:

- player identity continuity;
- transfers between clubs;
- promoted/relegated teams;
- fixture completeness;
- blank Gameweeks;
- double Gameweeks;
- postponed fixtures;
- player availability;
- price history;
- historical statistics;
- Gameweek deadlines;
- manager/team transitions.

A data problem must not be mistaken for a model failure.

---

# 30. Backtest special rules carefully

V0.8 should progressively improve historical rule fidelity.

Track explicitly:

- free transfers;
- transfer hits;
- Wildcard;
- Free Hit;
- Bench Boost;
- Triple Captain;
- blank Gameweeks;
- double Gameweeks;
- captaincy;
- automatic substitutions.

If different seasons use different FPL rules, introduce a season-specific ruleset rather than assuming today's rules apply identically to every historical season.

This can initially remain a separate abstraction from the prediction model.

Do not make these prerequisites for starting V0.8:

- deep-learning participation models;
- sophisticated NLP pipelines;
- autonomous transfer execution;
- automated scraping of every football-news source;
- complete bookmaker-style probabilistic match modelling;
- a major GUI redesign;

- production deployment infrastructure.

These may become later work once the core experiments justify them.

# 34. Recommended implementation philosophy

For every model change:

```text
Hypothesis
    ↓
Implement one change
    ↓
Run historical experiment
    ↓
Compare against frozen V0.7
    ↓
Inspect failure modes
    ↓
Accept / reject
```

Avoid combining many changes into one experiment because then we cannot identify why performance changed.

---

# 35. The most important V0.8 experiment

If only one experiment is completed, it should be:

> **Can a better participation model reduce the points lost by the optimizer due to unexpected non-appearances?**

Run:

```text
V0.7 predictor
      ↓
Production optimizer
      ↓
historical simulation

vs

V0.8 participation predictor
      ↓
same production optimizer
      ↓
same historical simulation
```

Then isolate:

```text
points gained
    specifically from
better participation prediction
```

This is the cleanest bridge between research and the actual product objective.

---

# 36. Expected V0.8 outcome

At the end of V0.8 we should be able to answer:

### Participation
> How likely is each player to start or appear?

### Minutes
> How many minutes should we expect conditional on that participation?

### Prediction
> Does the improved xM produce better xP predictions?

### Decision
> Does better xM/xP produce better transfer and lineup decisions?

### Strategy
> Is pure expected-point optimisation sufficient, or does rank-aware utility provide measurable benefit?

### Football context
> Which external football information actually improves predictions?

### LLM
> Does an LLM add useful qualitative information when presented with a deterministic shortlist?

These answers should determine V0.9.

---

# 37. V0.9 decision gate

At the end of V0.8, each major component should receive an evidence-based disposition:

```text
KEEP
```

if it consistently improves out-of-sample performance.

```text
CALIBRATE
```

if the concept works but requires parameter/model refinement.

```text
REDESIGN
```

if systematic errors remain.

```text
REMOVE
```

if the complexity does not produce measurable value.

The V0.9 roadmap should then be derived from those findings.
